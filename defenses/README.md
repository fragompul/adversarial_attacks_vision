# Defenses

Where `attacks/` shows how a model breaks, this folder asks what can be done about it. The four notebooks are ordered by how much they change: the first two leave the model untouched and act only at inference time, the third gives a provable guarantee instead of an empirical one, and the fourth is the only technique here that retrains the model itself.

`01_preprocessing_defenses` evaluates classic input-transformation defenses, JPEG compression, bit-depth reduction and spatial smoothing among them, by applying each to an adversarial example and checking whether the model recovers its original, correct prediction. It runs against the shared adversarial example bank built in `robustness_evaluation/10_generate_adversarial_dataset.ipynb`, so its numbers are only as complete as that manifest is; a version generated from a single placeholder image will only ever report a 0% or 100% recovery rate, which is a scale problem, not a bug.

`02_detection` takes a different angle: rather than trying to fix an adversarial input, it tries to flag it. It fits a Mahalanobis distance model over clean feature representations and measures how well the distance of a new image from that distribution separates adversarial examples from clean ones, reported as an AUROC score. Like the preprocessing notebook, its numbers depend on the same shared manifest.

`03_certified_robustness` implements randomized smoothing (Cohen et al., 2019): instead of measuring whether a specific attack happens to fail, it estimates a certified radius within which no attack, however clever, could possibly succeed, by classifying many noisy copies of an image and taking a statistical majority vote. This is the only defense in the folder with a mathematical guarantee attached to its output rather than an empirical measurement, at the cost of needing hundreds of forward passes per image to estimate.

`04_adversarial_training` is the one notebook here that changes the model. It fine-tunes TrafficNet (the GTSRB traffic-sign model, chosen because the three ImageNet CNNs used everywhere else are too large to retrain from scratch on a personal machine) with two objectives, PGD-AT (Madry et al., 2018) and TRADES (Zhang et al., 2019), and then re-measures the full attack battery, FGSM, PGD, DeepFool, C&W, Targeted I-FGSM and Square Attack, before and after training on the same held-out images. NES and Boundary Attack are deliberately left out of that comparison; see the notebook's configuration cell for the cost reasoning.
